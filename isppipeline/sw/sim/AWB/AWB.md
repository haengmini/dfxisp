# AWB — 적응 화이트밸런스 mAP 영향 시뮬레이션 방법론

## 1. 시뮬레이션 목표

`lowlight-wb-mode-split-2026-08-03.md` §0이 배포한 결론:

> 저조도 WB를 모드별로 분리하지 않는다. 배포된 공유 WB(`AWB_R/G/B =
> 286/256/307`)를 그대로 유지한다 ... 전 파라미터 범위(WB 완전 제거 ~ 2배
> 과보정)의 mAP spread가 **0.0020**으로, BLC 레버(0.0876)의 **1/44**에
> 불과하다.

이 결론은 세 겹 주장으로 이뤄진다:
1. **진단은 사실**: 배포 WB는 저조도(SonyNOD)에 필요한 B gain의 0.50배에
   불과해 객관적으로 잘못 맞춰져 있다(§2).
2. **그러나 반응 없음**: WB를 완전히 끄거나 gray-world까지 과보정해도
   mAP@[.5:.95]/mAP@50 스프레드가 각각 0.0020/0.0048에 그친다(§3.1).
3. **초가산적 패턴이 효과 자체를 반증**: R만 이동(−0.05%), B만 이동
   (−0.19%)인데 둘 다 이동하면 +0.61%로 뒤집힌다 — 물리적 메커니즘이 있는
   효과라면 나올 수 없는 부호 패턴이다(§3.2).

**이 문서가 검증할 것**: 이 결론에 이른 방법론이 얼마나 엄밀했는지 정리하고,
재현 절차를 명시한다. binning/blc 두 모듈과 달리 이 모듈은 신규 설계가
아니라 "이미 있는 걸 재현 가능하게 정리하는 것"이 과제다 — gamma.md와
동일한 성격이지만, gamma와 달리 근거 문서와 원자료가 **다른 워크트리가
아니라 이 브랜치의 라이브 트리에 그대로 있다**(§2.4).

## 2. 시뮬레이션 이론

### 2.1 WB가 적용되는 도메인과 gray-world 진단

WB는 bin-demosaic → BLC 감산 직후(RAW16 도메인)에 채널별 곱셈으로
적용된다(`gen_lowlight_isp_golden.py`의 `correct_channel()`, gain.md §2.3
참고). `lowlight-wb-mode-split-2026-08-03.md` §2가 바로 이 도메인에서 정본
데이터셋의 채널 평균을 실측해 gray-world 기준 WB(G=256 고정, R/B는
`256 * mean_G / mean_ch`)와 배포값을 비교했다:

| 항목 | SonyNOD (저조도) | PASCALRAW (밝음) |
|---|---:|---:|
| 채널비 B/G | 0.416 | 0.765 |
| gray-world WB (Q8, G=256) | R 435 / B 616 | R 538 / B 335 |
| 배포값(286/256/307) / gray-world | R 0.66× / B 0.50× | R 0.53× / B 0.92× |

배포 WB는 사실상 밝은 장면(PASCAL)에 맞춰져 있고(B 0.92×로 거의 정확),
저조도(SonyNOD)에는 청색 보정이 절반만 걸린다 — **진단 자체는 사실**이다.

### 2.2 mAP 스윕 설계

SonyNOD(`lod_split`, n=321), `lowlight` arm 단독, BLC=2 고정, YOLOv8n,
`imgsz=640`. WB 후보 6개로 `AWB_R/G/B` 조합을 스윕한다(`WB 완전 off
256:256:256`부터 `gray-world 435:256:616`까지, §3.1 원표 그대로).

### 2.3 반응하지 않는 이유(해석, §4 인용)

1. 채널별 전역 gain은 대각 선형변환이라 에지·형태 등 공간 구조를 바꾸지
   않는다 — 검출은 공간 구조에 의존한다.
2. COCO 사전학습 검출기는 다양한 조명에서 학습돼 전역 색 캐스트에 이미
   상당히 불변이다.
3. WB는 BLC 클리핑 **이후**에 적용되는데, BLC=2에서도 저조도 픽셀의
   52~73%가 이미 0으로 클리핑돼 있어 WB가 작용할 여지 자체가 제한적이다.
4. 이후 gamma 2.0(sqrt)이 남은 채널 차이를 추가로 압축한다.

### 2.4 기존 근거와 재현 가능성

| 근거 | 위치 | 재현 가능성 |
|---|---|---|
| 결론과 6-후보 mAP 스윕 원자료 | `lowlight-wb-mode-split-2026-08-03.md` §3, `results/wb_sweep_lowlight_2026-08-03.csv` | ✅ **라이브 트리, 정본.** 문서와 CSV 둘 다 이 브랜치에 그대로 있다 — gamma.md의 워크트리 전용 상황과 달리 즉시 열람 가능. |
| §2의 채널 통계 진단(gray-world 비교, BLC 클리핑률) | 같은 문서 §2 | **재현 불가 — 원본 스크립트 없음.** "`tools/` 외부 임시 스크립트, 픽셀 stride 4"라고만 서술돼 있고 스크립트 자체는 저장되지 않았다. 수치(표)는 라이브 문서에 남아 있으므로 결론 인용은 가능하지만, 새 데이터로 같은 진단을 다시 돌리려면 스크립트를 새로 짜야 한다. |
| mAP 스윕을 만든 하네스(`tools/eval_map_isp.py --wb-lowlight`, `low_light_isp_pipeline.run_lowlight(..., wb=None)`) | 원 문서 §6 "남긴 산출물" | **현재 브랜치엔 없음.** 이 브랜치의 `isppipeline/sw/lowlight_isp_pipeline.py`는 `run_lowlight_isp(bayer16, w, h, bm, tm)`뿐이고 `wb` 오버라이드 파라미터가 없다 — mAP 스윕 자체를 재실행하려면 이 파라미터와 `--wb-lowlight R,G,B` 스타일 CLI를 다시 추가해야 한다. |
| 배포 WB 상수 자체(`WB_R_Q8=286` 등) | `gen_lowlight_isp_golden.py` | ✅ 라이브 트리, 정본 구현. gain.md §2.3이 참조하는 것과 동일. |
| 07-02 combined / 07-03 분리 ablation(이 실험 이전의 두 선행 검증) | `lowlight-rm-map-rootcause-2026-07-02.md` §1.2, `phase0-2-execution-2026-07-03.md` §1.1/1.2 | 참고용 인용만 — pseudo-RAW(카메라 AWB를 이미 거친 데이터) + BLC=16(대부분 0-클리핑) 조건의 구조적 결함이 있어 08-03 문서가 재검증한 배경(§1)일 뿐, 이 문서의 결론 근거로 재사용하지 않는다. |

**요약**: 이 모듈은 gamma.md와 같은 "흩어진 걸 모아 재현 가능하게 만드는
것"이 과제이지만, gamma보다 사정이 낫다 — 결론과 원자료(CSV)는 이미 이
브랜치에 있고, 없는 건 (a) 채널 진단을 만든 일회성 스크립트와 (b) mAP
스윕을 재실행할 하네스 파라미터뿐이다.

## 3. 시뮬레이션 방법 (기존 방법론 재현)

### 3.1 1단계 — 결론 재확인 (재실행 불필요)

`results/wb_sweep_lowlight_2026-08-03.csv`를 그대로 읽어 spread를
재계산하는 것만으로 §0의 결론을 확인할 수 있다:

```text
WB 전 범위 spread (off ~ 2배 과보정) : mAP@[.5:.95] 0.2134~0.2154 = 0.0020
BLC 레버 (07-03 실측, 16 -> 8)       : 0.0619 -> 0.1495 = 0.0876   (44배)
```

CSV가 라이브 트리에 있으므로 이 단계는 스크립트 없이 표 계산기로도 즉시
검증 가능하다.

### 3.2 2단계 — mAP 스윕 재실행 (하네스 파라미터 복원 필요)

원 스윕을 새 데이터나 새 후보로 재현하려면:
1. `lowlight_isp_pipeline.run_lowlight_isp()`에 `wb: tuple[int,int,int] |
   None = None` 파라미터를 추가하고, `None`이면 `WB_R_Q8/WB_G_Q8/WB_B_Q8`
   기본값을, 아니면 전달된 3-튜플을 쓰도록 한다(§2.4 표의 gap).
2. 평가 하네스(`eval_map_isp.py` 계열, 현재 브랜치엔 없음)에 `--wb-lowlight
   R,G,B` 같은 CLI 오버라이드를 추가한다.
3. §3.1 원표의 6개 후보(off/배포값/R만 이동/B만 이동/R+B 중간/R+B
   gray-world)를 동일 조건(SonyNOD n=321, BLC=2, YOLOv8n)으로 재실행한다.

### 3.3 3단계 — 판정 기준

원 문서와 동일한 두 기준을 그대로 쓴다:
- **규모**: 전 범위 mAP spread가 BLC 레버(0.0876) 대비 얼마나 작은가 —
  1/44 이하로 재현되면 "레버 아님" 재확인.
- **부호 패턴(§3.2 핵심)**: R만/B만 단독 이동이 각각 음의 방향이고 둘 다
  이동했을 때만 양의 방향으로 뒤집히는 초가산적 패턴이 재현되는지 — 이
  패턴이 사라지고 단조로운(monotonic) 부호로 나온다면, 이전 결론이
  잡음(jitter)이 아니라 실제 신호였을 가능성이 있으므로 재검토 대상이다.

## 4. 알려진 한계

- 이 문서는 "저조도 WB를 손보자"는 제안이 아니다 — §1의 기각 결정을
  뒤집을 근거가 나오지 않는 한, 재현 절차는 "결론이 여전히 성립하는지
  확인"하는 회귀 검증 용도로만 쓴다.
- §3.2의 하네스 파라미터(`wb` 오버라이드, `--wb-lowlight` CLI)를 복원하지
  않으면 1단계(§3.1, CSV 재계산)만 즉시 가능하고 새 스윕은 못 돌린다.
- 원 문서 §7이 남긴 미착수 후속 후보 두 가지는 이 문서 범위 밖이다:
  - **BLC=0 미검증**: 정본 캠페인은 `--blc-offsets 16,1,2`만 돌렸고 0은
    빠졌다. §2.1에서 BLC=2에서도 저조도 픽셀의 52~73%가 0으로 클리핑되는
    것이 확인됐으므로, BLC=0이 근-흑색 픽셀을 살려 WB의 작용 여지를 넓힐
    가능성은 열려 있다.
  - **교차 모델 미검증**: 결론은 YOLOv8n 기준. 효과 크기가 잡음 수준이라
    뒤집힐 가능성은 낮지만, 진행 중인 YOLOv8s 교차검증에서 함께 확인
    가능.
- §2.4의 채널 진단(gray-world 비교, BLC 클리핑률)은 일회성 스크립트로
  만들어져 원본이 남아 있지 않다 — 표의 수치는 인용할 수 있지만, 다른
  데이터셋이나 다른 BLC 값에 대해 같은 진단을 새로 돌리려면 스크립트를
  재작성해야 한다(binning.md/blc.md가 캘리브레이션 스크립트
  `calibrate_noise_model.py`를 재사용하는 것과 대비되는 지점).

## 5. 산출물 (구현 완료, 2026-08-12 LOD_test 실행)

§2.4/§4가 지적한 두 gap을 dataset/LOD_test 대상으로 메웠다 — 아래는 실행
후 실제 산출물이며, 각주로 남긴 "구현 시" 계획을 대체한다:

- `AWB_report.md` — §3.1 규모 판정 + §3.2 부호패턴 판정을 LOD_test로
  재실행한 회귀 리포트. §3.2의 초가산적 부호패턴은 LOD_test에서 그대로
  재현되지 않았다(§4 한계 항목에 반영) — 결론(레버 아님) 자체는 유지.
- `awb_channel_diagnostic.py` — §2 채널 진단(gray-world 비교)의 신규
  구현. 원 스크립트는 여전히 소실 상태(위 표 그대로 유지)지만, 이
  스크립트가 같은 진단을 처음부터 다시 만들어 LOD_test/향후 다른
  데이터셋에도 재사용 가능하다.
- mAP 스윕 하네스: `wb` 오버라이드는 이 브랜치의 `lowlight_isp_
  pipeline.py`(v2)가 아니라, 워크트리 `hw-interface-prompt`의
  `low_light_isp_pipeline.py`(v1, `eval_map_isp.py`의 `lowlight` arm이
  참조)에 이미 구현돼 있었다 — 새로 만들 필요 없이 그 자리에서
  실행했다(gamma.md §5와 같은 원칙). 이 브랜치의 v2 `lowlight_isp_
  pipeline.py`에 `wb` 파라미터를 추가하는 것은 여전히 미착수다.
