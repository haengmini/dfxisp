# Checker 강화 전략 (항목별 실행 계획, 2026-07-09)

**작성:** 2026-07-09 KST · **브랜치:** `exp/principled-checker-rm-2026-07-05`

> 전제: `checker-sota-review-2026-07-09.md`의 7개 강화안을 실행 가능한 단위로
> 구체화한다. 각 항목은 **목표 → 설계 → 구현 단계 → 평가 프로토콜 →
> 수용/기각 기준 → 리스크 → 의존성·공수**로 고정한다. 공통 원칙:
> (a) 모든 후보는 C4를 기각시킨 것과 같은 **정직한 nested-CV + fold-분산
> 마진 기준**을 통과해야 채택, (b) 비용모델은 R = ½(miss·C_miss + FT·C_FA),
> C_miss=0.1118 / C_FA=0.0387을 유지하되 #4 완료 후 재보정, (c) HW 후보는
> 반드시 "1-pass 정수 스트리밍 + AXI-lite 파라미터" 계약을 지킨다.

**현행 기준선(비교 대상):** C1 `dark16 > 0.62` + 히스테리시스 δ=2%p —
recall 0.936 / FT 0.089 / J 0.847 / R 0.00531. 모든 전략의 개선은 이
기준선 대비로 보고한다. 채택 마진의 최소 단위는 5-fold FT fold-분산
±0.03~0.04 (simulation §6) — **이보다 작은 개선은 기각**한다.

## #1 센서 메타데이터 적응 임계 τ(exposure, gain, blc)

**목표.** 합성 pseudo-RAW에서 보정된 고정 상수 dark16(=raw12 256)을,
실센서의 노출 s·아날로그 게인 g·블랙레벨 BLC에 따라 움직이는 τ(s,g)로
대체한다. 실HW 이식 시 최대 실패요인(임계 절대값의 도메인 붕괴) 제거.

**설계.** 원리 3(노이즈물리)의 정본화. dark 임계를 "노이즈 플로어에서
유의하게 벗어나지 못한 픽셀"로 정의한다:

```
τ(g) = BLC(g) + k·σ_read,DN(g),   σ_read,DN(g) = σ_read,e⁻ · g / K
```

- σ_read,e⁻, 변환게인 K는 EMVA 1288 절차(플랫필드/다크프레임 시퀀스)로 1회
  캘리브레이션. k는 Rose criterion(s≈5)을 초기값으로 스윕.
- 노출 정규화: 판정은 scene-referred 광량 축에서 해야 하므로, 동일 장면이
  s·g만 바뀔 때 판정이 불변이 되도록 τ를 상대노출 (s·g)/(s₀·g₀)로 스케일
  하거나, 동등하게 히스토그램 자체를 시프트해 읽는다(정수 시프트로 실현).

**구현 단계.**
1. τ(s,g) 파라메트릭 모델 유도 문서 + `tools/checker_adaptive_tau.py`
   프로토타입 — EXIF(ISO, 노출시간, 조리개)에서 τ 계산. **AODRaw 불필요,
   지금 착수 가능(수식·스캐폴드까지).**
2. AODRaw 도착 후: EXIF 파싱 → 프레임별 τ 산출 → ISO/노출 스트라텀별로
   고정-τ vs 적응-τ의 recall/FT 비교 스윕.
3. k 스윕(3~7)과 τ 상하한 클램프 결정.
4. HW 반영 — **경로 A(권장, RTL 변경 0):** `dark_pixel_threshold`가 이미
   AXI-lite 런타임 레지스터(`dfxisp_accel.cpp:403`)이므로, 호스트 드라이버가
   센서 설정 변경 시점마다 τ를 계산해 레지스터에 써넣는다. **경로 B:**
   (게인 인덱스 × 노출 버킷) 소형 2D LUT를 체커 앞단에 합성 — 드라이버
   개입 없이 완전 자율일 때만.

**평가 프로토콜.** AODRaw를 EXIF ISO로 3~5개 스트라텀으로 나누고, 스트라텀별
recall/FT/J를 고정 dark16과 적응 τ에서 비교. 고정 τ의 스트라텀 간 성능
분산(열화) 자체가 ablation 근거가 된다.

**수용 기준.** 적응 τ가 (i) 전 스트라텀에서 J ≥ 고정 τ, (ii) 스트라텀 간
recall 분산을 유의하게 축소. **기각 기준.** AODRaw의 노출 다양성이 낮아
고정 τ와 차이가 fold-분산 이내면, "AODRaw 범위에서는 고정 τ 충분"으로
기록하고 경로 A만 문서화(HW는 이미 레지스터라 기각 비용 0).

**의존성·공수.** 1단계는 즉시(0.5일), 2–3단계는 AODRaw 필요(1~2일).
센서 실기 EMVA 캘리브는 보드 단계로 연기 — AODRaw EXIF 기반 근사로 선행.

## #2 히스토그램 우도비 (학습형 선형 LRT)

**목표.** dark-ratio(CDF 1점)의 정보이론적 상한(data-processing inequality,
theory §1.3)을 돌파. 잔존오차 74장(ExDark miss 29 + COCO FT 45) 중 꼬리
분포 케이스 회수.

**설계.** 이미 1-pass로 계산되는 256-bin 히스토그램 h_b(raw>>8) 위의 선형
판별:

```
score = Σ_b w_b · ĥ_b,   ĥ_b = h_b/N,   w_b ≈ log p(b|H₁)/p(b|H₀)
LOW_LIGHT ⇔ score > t
```

- 학습: L2(또는 L1) 정규화 로지스틱 회귀. **w의 단조성/평활 제약**(인접 bin
  차분 페널티)을 걸어 과적합과 OOD 취약성을 억제 — C4 기각 사유(OOD 위험)에
  대한 구조적 방어.
- 양자화: w_b를 int8~int16으로 양자화해 HW와 SW 점수를 비트일치시킨다.
- 저비용 변형(fallback): 256-bin 대신 8~16-bin 로그 간격 coarse 히스토그램
  — theory §2.2/§6.3에서 "기각 아닌 연기"로 분류된 방향.

**구현 단계.**
1. `checker_stat_sweep.py --compute`를 확장해 프레임별 **전체 256-bin
   히스토그램 덤프**(현 CSV는 요약통계 108열만) — 새 파일
   `results/scratch_frame_hist.npz`.
2. `tools/checker_lrt.py`: 학습 + **nested 5-fold CV**(C4에 썼던
   `checker_versions_fine.py`의 정직한 프로토콜 재사용) + 양자화 후 재평가.
3. 잔존오차 74장 대상 회수율 별도 보고(전역 지표와 분리).
4. 채택 시 HW 설계: 256-entry weight ROM(1 BRAM) + MAC 누산기 1개 +
   비교기 — 스트리밍 계약 유지, 기존 카운터 자리에 누산기.
5. AODRaw 도착 후 OOD 검증: COCO/ExDark로 학습한 w를 AODRaw에 무재학습
   적용 → 일반화 확인(이게 진짜 채택 관문).

**평가 프로토콜.** (i) nested-CV held-out J/R vs C1, (ii) 양자화 손실
ΔJ < 0.005 확인, (iii) 잔존 74장 회수 수, (iv) AODRaw zero-shot 전이.

**수용 기준.** held-out J가 C1(0.847) 대비 **+0.04 이상**(fold-분산 초과)
그리고 AODRaw 전이에서 붕괴 없음. **기각 기준.** C4처럼 in-sample만 이기고
nested-CV 마진이 fold-분산에 묻히면 기각 — 단 coarse 8~16-bin 변형을
한 번 더 시도한 뒤 기각을 확정한다.

**의존성·공수.** 1–3단계 AODRaw 불필요, 즉시 착수 가능(1~1.5일).
5단계만 AODRaw 대기. **데이터 무관 착수 후보 중 레버리지 최대.**

## #3 순차 변화탐지 시간층 (CUSUM/SPRT)

**목표.** K-of-N + Schmitt(현 스케줄러 계획)를 우도비 누산 기반 온라인
변화탐지로 대체 — 같은 오전환율에서 탐지지연을 줄이고, PR 비용 c_PR을
정지경계에 명시적으로 반영한다.

**설계.** 프레임별 점수 s_t(현행 dark16 ratio 또는 #2 score)에 대해:

```
CUSUM:  g_t = max(0, g_{t−1} + (s_t − t₀ − ν)),  전환 ⇔ g_t > h
SPRT :  L_t = L_{t−1} + log Λ(s_t),  A < L_t < B 유지, 경계 이탈 시 판정
```

- ν(drift)는 히스테리시스 δ의 순차판 — 경계 근방 잡음 흡수.
- h(또는 A,B)는 목표 ARL(average run length)로부터: 정상 상태 오전환
  주기를 PR 빈도 예산(예: 오전환 ≤ 1회/10분)으로 설정하고 역산.
- c_PR 반영: 전환의 기대이득 Δmiss·C_miss·(체류 기대프레임) > c_PR일 때만
  경계를 넘도록 h를 하한 보정 — renewal-reward 근사.
- 방향별 비대칭: 진입(NORMAL→LOW_LIGHT)은 C_miss가 크므로 낮은 h,
  해제는 높은 h — 기존 enter 64%/exit 60% 비대칭의 일반화.

**구현 단계.**
1. `checker_stat_sweep.py`의 `flap_sim`(캘리브레이션된 지터 σ: median
   0.0023 / p95 0.0055)을 시퀀스 생성기로 확장 — steady / ramp / 깜빡임
   (조명 플리커) / 스텝 시나리오.
2. `tools/checker_temporal.py`: 단일임계 / Schmitt / K-of-N / CUSUM / SPRT
   5개를 동일 시퀀스에서 비교. 지표: (탐지지연 프레임, 오전환/100fr,
   steady flap) 파레토 곡선.
3. 채택 시 HW: 누산 레지스터 1개 + 비교기 — Schmitt의 mode FF 1개에서
   레지스터 1개 추가로 끝. `checker_select_mode`에 이전 모드 입력과
   누산 상태 입출력을 추가(인터페이스 변경 소폭).
4. 실검증: AODRaw는 스틸이므로 시간축 실검증은 불가 — 스틸에서 노출
   램프를 합성(EXIF 노출 스케일링)해 근사하고, 최종 검증은 보드 비디오로
   연기함을 명시.

**수용 기준.** 동일 오전환율에서 Schmitt+K-of-N 대비 탐지지연 ≥30% 단축,
steady flap 0.00 유지. **기각 기준.** 지터 σ가 작아(측정치 0.002 수준)
Schmitt만으로 이미 flap 0이고 지연 차이도 1~2프레임이면 — "Schmitt 충분,
CUSUM은 실센서 지터 측정 후 재검토"로 기록.

**의존성·공수.** 전부 AODRaw 불필요, 시뮬레이터 확장 포함 1일.
보드 전 최종 채택은 불가(실지터 미측정)임을 결과 문서에 못박는다.

## #4 평가·라벨 재정의 (다운스트림 오라클 + 조도 연속축) — AODRaw 착수 시 최우선

**목표.** COCO=NORMAL / ExDark=LOW_LIGHT라는 데이터셋 프록시 라벨을,
"그 프레임을 어느 모드로 라우팅해야 검출이 좋아지는가"라는 **다운스트림
오라클 라벨**로 교체. 잔존오차 74장의 라벨 아티팩트 문제 소거, 이후 모든
체커 평가의 기준 재정립.

**설계.**
- **오라클 라벨:** 프레임 f마다 두 arm(normal / low-light)을 모두 렌더 →
  yolov8n → 프레임별 검출 델타 Δ(f) 계산. `y*(f) = argmax arm`,
  |Δ(f)| < ε인 프레임은 **don't-care 밴드**로 분리(체커가 뭘 골라도 무방).
- 프레임별 지표: 프레임 단위 mAP는 고분산이므로 매칭 기반 스코어
  (IoU≥0.5 매칭 TP의 confidence 합 − FP 페널티)를 1차로 쓰고, 집계
  검증은 mAP로 이중화.
- **조도 연속축:** AODRaw EXIF(ISO×노출시간)로 프레임을 조도 프록시 축에
  배열 → recall/FT를 이 축의 함수로 보고(이진 데이터셋 경계가 아니라
  전이곡선을 봄). 체커 점수의 확률 보정 품질은 ECE로 보고.

**구현 단계.**
1. **AODRaw 어댑터**(선결, 임계경로): 실RAW 로더 — 비트뎁스/BLC/Bayer
   패턴/EXIF를 파이프라인 raw12 계약으로 정규화.
   `tools/aodraw_adapter.py`. 다운로드 완료 전에 포맷 스펙만으로 작성 가능.
2. `scratch_adaptive_map_principled.py`를 프레임별 **dual-arm 러너**로 확장
   (`newrm_pipeline.run_arm` 재사용) → per-frame Δ CSV.
3. 오라클 라벨 생성 + don't-care ε 스윕(Δ 분포의 노이즈 플로어로 결정).
4. C0–C4 + #2 LRT를 오라클 라벨로 전면 재평가. C_miss/C_FA도 오라클
   Δ 분포에서 재추정(현 n=31/39 ablation을 대체).
5. C1 운영점(0.62)과 C1 vs C2(0.62 vs 0.553) 결정을 재보정.

**수용 기준.** (i) 기존 잔존오차 74장 중 라벨 아티팩트로 판명되는 비율
정량화, (ii) 오라클 기준 운영점의 신뢰구간 제시, (iii) don't-care 밴드
크기 보고(밴드가 크면 "체커 정밀도는 이미 충분" — 그 자체가 논문 결론).
이 항목은 채택/기각이 아니라 **평가 인프라라 무조건 수행**.

**리스크.** yolov8n CPU 전수(dual-arm × 프레임 수)는 wall-clock이 큼 —
n=150 서브셋으로 프로토콜 확정 후 전수는 야간 배치로. AODRaw 라벨 형식이
COCO 클래스와 다르면 클래스 매핑 테이블 필요.

**의존성·공수.** 1단계는 지금(0.5일), 2–5단계는 AODRaw 완료 후 2~3일
(+ 배치 러닝 타임).

## #5 공간(타일) 미터링

**목표.** 전역 비율이 놓치는 역광/스포트라이트(공간 구조) 실패 복구.

**설계.** 프레임을 4×4 타일로 나눠 타일별 dark16 카운터(16개). 결합 규칙
후보 3개를 경쟁: (a) center-weighted 가중합(전통 미터링), (b) M-of-16
(dark 타일 수 ≥ M), (c) 전역 비율 AND/OR 타일 극값. 검출 ROI saliency
가중은 후속(피드백 루프 필요라 보드 단계).

**구현 단계.**
1. **잔존오차 74장 국한 선행 검증**(싼 관문): 기존 .bin에서 74장의 타일
   통계를 뽑아 "공간 구조 가설"이 실제 몇 장을 설명하는지 센다.
   `tools/checker_tile_probe.py`.
2. 가설이 서면(≥1/3 설명) 전수 1150 스윕 + nested-CV로 결합 규칙 선택.
3. 채택 시 HW: 카운터 16개 + 소형 결합기 — 스트리밍 중 타일 인덱스는
   (x>>log2(W/4), y>>log2(H/4))로 무곱셈 산출.

**수용 기준.** 74장 중 유의미 회수 + 전역 J 손해가 fold-분산 이내.
**기각 기준.** 1단계에서 74장 대부분이 공간 구조가 아니라 전역 조도
자체가 경계인 케이스로 나오면 즉시 기각(1단계가 싸므로 기각 비용 최소).

**의존성·공수.** AODRaw 불필요. 1단계 반나절, 전체 1일.

## #6 확률 캘리브레이션 + 전환 기대효용 판정

**목표.** 경계밴드 프레임(모든 mAP 액션이 발생하는 곳)에서 점수를 보정된
확률로 바꾸고, 전환 결정을 c_PR 포함 기대효용으로 내린다.

**설계.**
- 보정: 체커 점수 → P(H₁|score) 단조 매핑(isotonic 또는 Platt) → 256-entry
  LUT로 고정. 품질은 ECE/신뢰도 다이어그램으로 보고.
- 판정: 현재 모드 m에서 전환은
  `E[ΔRisk·체류프레임] > c_PR` 일 때만 — 히스테리시스·don't-care 밴드의
  원리적 일반화이며 #3의 경계 설정과 같은 식을 공유(따라서 #3과 한
  캠페인으로 묶어 수행).

**구현 단계.** 1) CV fold에서 보정 학습 + ECE 보고(`checker_lrt.py`에
동승), 2) c_PR 자리표시자(보드 측정 전은 t_PR≈수 ms 가정 범위 스윕)로
전환 정책 민감도 분석, 3) HW는 LUT 1개 — #2 채택 시 무료에 가깝다.

**수용 기준.** ECE < 0.05 및 기대효용 정책이 고정 히스테리시스 대비
시뮬레이션 R을 개선. **의존성.** #2/#3에 동승, 단독 공수 0.5일.

## #7 3-모드 이산화 (normal / low / extreme-low)

**목표.** 극저조도에서 2×2 binning + gain 2.0의 톤 헤드룸이 부족한 구간을
제3 RM(예: 4× binning 또는 강한 톤맵)으로 분리.

**전략 — 착수 게이트만 정의(지금 하지 않음).** #4의 조도 연속축 결과에서
`저조도 arm으로도 mAP가 붕괴하는 lux 구간`이 통계적으로 확인될 때만
착수한다. 게이트 통과 시: (i) 오라클 Δ 곡선에서 제2 변곡점으로 극저조도
경계 산출, (ii) 2-임계 체커(기존 비교기 1개 추가)로 라우팅, (iii) RM 슬롯
추가에 따른 PR 자원/빈도 비용은 DFX Ctrl 캠페인에서 별도 산정.
**#4 완료 전 착수 금지** — 지금 만들면 프록시 라벨 위에 모드 경계를
긋는 셈이라 전부 재작업이 된다.
