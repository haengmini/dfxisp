## 4. §3.4 — 0-클리핑 발생률과 "저조도 픽셀 52~73% 클리핑" 가설

| s | R: a / b | G: a / b | B: a / b |
|---:|---|---|---|
| 0   | 98.8% / 65.3% | 100.0% / 52.4% | 98.8% / 66.4% |
| 8   | 93.3% / 45.4% | 98.2% / 27.6%  | 93.8% / 45.2% |

| 64  | 5.9% / 0.2%   | 0.9% / 0.0%    | 5.2% / 0.3%   |
| ≥96 | ~0% / ~0%     | ~0% / ~0%      | ~0% / ~0%     |

**뜻밖의 결과: 방향이 반대다.** order a(배포 순서)의 0-클리핑 발생률이
전 신호준위·전 채널에서 order b보다 **일관되게 높다** (교차점 없음 —
R/B는 s=128, G는 s=96에서야 둘 다 0%로 같아진다). 이유는 두 순서가
"클리핑"을 서로 다른 단위에서 겪기 때문이다:

- order a: 평균(분산이 이미 1/n로 줄어든 값) **하나**가 floor 문턱을
  넘는지만 본다 — 참신호가 낮으면 평균 자체가 거의 항상 문턱 밑에
  있으므로 발생률이 매우 높다.
- order b: **개별 샘플 n개**(R/B=4, G=8) 중 **전부**가 문턱 밑이어야
  최종 평균도 0이 된다 — 샘플 하나라도 살아남으면 출력이 0이 아니게
  되므로, 개별 클리핑 확률이 훨씬 높은데도(§2.1의 애초 주장대로) 최종
  0-클리핑 발생률은 오히려 낮다.

즉 **"편향 크기"(기준 1: order b가 항상 더 나쁨)와 "0-클리핑 발생률"
(order a가 항상 더 높음)은 서로 다른 방향을 가리키는 별개의 지표**다.
`lowlight_isp.md` §2.5의 "저조도 픽셀 52~73%가 0으로 클리핑되는 게 이
순서 탓일 수 있다"는 가설은 이 결과로 보면 **반증까지는 아니지만
방향이 어긋난다** — 순서를 반대로 바꾸면(order b) 오히려 0-클리핑
발생률은 낮아진다. "52~73%"는 order a 자체의 특성(도표상 R/B는
s≈16~24, G는 s≈8~16 부근에서 그 범위를 지난다)이지, 순서를 바꾸면
해소될 문제가 아니다.

## 6. 결론

- §2.1의 **정성적** 주장(순서 a가 순서 b보다 덜 편향됨, 고신호에서
  수렴)은 기준 1·3에서 예외 없이 확인됐다.
- 그러나 "평균 후 감산이 **비편향**"이라는 **정량적** 주장은 pedestal
  근방(0~64 DN)에서는 성립하지 않는다 — 작지만 통계적으로 유의한
  잔여 바이어스가 order a에도 있다(floor가 완전히 사라지지 않기
  때문). 이 구간을 벗어나면(96 DN 이상) 대체로 0과 구별되지 않는다.
- s≈2048 부근의 이상치는 BLC 순서와 무관한 EXPOSURE_GAIN 포화
  아티팩트로, `blc.md`의 스코프(BLC 순서) 밖이다 — 별도 이슈로
  다룰 가치가 있다면 `gain.md`쪽에서 다뤄야 한다.
- "저조도 52~73% 클리핑"과 BLC 순서를 연결하는 가설은 이 시뮬레이션이
  반증하지는 않지만, 방향이 기대와 반대(order a가 오히려 클리핑률이
  더 높음)라 순서 변경으로 그 클리핑률을 낮출 수 있다는 근거로는
  쓸 수 없다.

`blc.md` §4의 한계(통계적 편향만 측정, 검출 mAP 영향은 범위 밖)는
그대로 적용된다.
