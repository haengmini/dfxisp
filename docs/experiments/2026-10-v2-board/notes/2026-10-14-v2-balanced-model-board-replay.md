# v2 균형 학습 모델: FP32 → INT8 → 보드 DPU 재생 (2026-10-14)

## 범위와 한계 (먼저 읽을 것)
- 이 문서의 보드 수치는 **미리 렌더링한 무손실 RGB를 보드 DPU에 입력한 재생(DPU-only replay)** 결과다. 보드 ISP(RM) → DPU 전체 경로가 아니다. 콜드 부팅·ICAP·DFX 가드는 사용하지 않았다.
- 시험 프레임(야간 100·주간 100)은 이미 여러 실험에 노출됐다. 새 장면 holdout이 아니다.
- 주간 학습자료는 PASCALRAW **축소 JPG replay**(ISP 주간 RAW 아님)이다.
- ISP 효과와 모델/데이터 효과를 구분해야 한다. 아래 부트스트랩은 **시험 프레임 표본** 불확실성만 반영한다(학습 시드 편차는 별도 표기).

## 모델·데이터
- 모델: 프로젝트 YOLOv8n 3클래스, Hardswish를 학습 전에 적용, 640 stretch 사전 적용, SGD lr0 .002, 30 epoch, 마지막 가중치만 사용(시험 점수로 체크포인트 선택 안 함).
- 학습: 야간 원본 1,335장(기존 359 + Drive 신규 976) × (NormalISP + LowlightISP BLC16) + 주간 replay 899. 검증: 야간 신규 260(두 ISP), 주간 201.
- 선택: A_full(전체 학습)을 **개발 검증**으로 선택. B_freeze10(앞 10층 고정)도 같은 시험으로 병기.
- 양자화: Vitis AI NNDCT PTQ, 보정 128장(**학습 분할만**: 야간 Normal 40, 야간 Lowlight 40, 주간 48). 시험·검증 프레임 0장.
- 컴파일: DPUCZDX8G_ISA1_B4096, 지문이 기존 배포 모델과 동일(`0x101000056010407`). 기존 배포 모델은 DPU 서브그래프 2개(DFL 후처리 포함), 새 모델은 1개.

## 호환 모델 동등성 게이트
- Vitis AI 컨테이너(ultralytics 8.3.0)와 학습 환경(8.4.174)의 헤드 구조가 달라, 컨테이너에서 헤드를 재구성하고 BN eps/momentum을 맞춤.
- 8장×6텐서 최대 절대 차이 **0.0** (EQUIV_PASS). 처음에는 0.045 차이가 있었고 BN eps 차이가 원인이었다.

## 보드 live 측정 (RAW → 보드 ISP → v2 DPU, 2026-10-15 콜드 부팅 후)
- 조건: 사용자 콜드 부팅 확인, 가동 217초, DFXC 0x7 / GUARD 0x0, PCAP_PR 1→0 (`PCAP_PR_CLEAR_VERIFIED`, `ICAP_SELECTED_OK`). BOOT.BIN·기존 Normal/BLC32/BLC16 파셜 해시 불변(실행 후 재확인). 종료 후 GUARD 0x5는 ISP 세션 사용 흔적이며, 다음 ISP 세션 전에는 다시 완전 전원 off/on이 필요하다.
- 구성: Normal = 기존 `partial_normal_bs1`, Lowlight = **BLC16** `partial_lowlight_blc16_bs1`(RM 고정, 프레임마다 전환 없음). 야간 100 + 주간 100, 각 2 ISP = ISP 400프레임 + DPU 400회. 체커 자동 선택은 live에서 쓰지 않았고 adaptive 열은 체커 판정에 따라 두 live 출력 중 하나를 오프라인으로 고른 값이다.
- 게이트: 매 프레임 보드 RGB의 SHA256이 PC 기준과 일치해야 진행(불일치 시 즉시 중단). **400/400 일치**, 보드 RGB 기준 해시는 이전에 보드 검증된 스모크 2장(Normal PASCAL/2014_000018, BLC16 Lowlight LOD/DSC01133)과도 일치.
- 보드 live 검출 400건이 DPU 단독 재생 검출과 **완전히 동일**(400/400).

- **주간은 개선이 아니라 시드마다 갈림**: 시드 0은 +0.013~+0.026(CI가 0 포함), **시드 1은 Normal −0.032 [−0.062,+0.003], Adaptive −0.051 [−0.084,−0.019](CI가 0 미만)**, 시드 2는 −0.012~+0.007. 시드 평균은 기존과 같거나 약간 낮음(Normal 0.6270 vs 0.6374). 양자화 전 FP32 시험에서는 시드 1 주간이 0.6596(Normal)이었으므로 INT8에서 주간이 크게 떨어진 시드가 있다(시드 1 호스트 INT8 주간 0.606). 주간 성능 "유지"는 시드에 따라 성립하지 않을 수 있다.

### 보드 vs 호스트 INT8 불일치 (진단 결과)
- YOLO와 달리 SSD는 보드와 호스트 INT8의 검출 리스트가 **이미지 단위로 일치하지 않는다**(일치 0/400). 파이프라인 단계(전처리·이름 매칭·순서)의 명백한 오류는 찾지 못했으나, 원인은 **미해결**이다.
  - 같은 입력 4장의 원시 출력 비교(회귀/분류 텐서): 보드−호스트 시뮬레이션 상관 0.98~0.99, 평균 절대 차이 0.07(회귀)·0.16~0.22(분류). 호스트 시뮬레이션−FP32 상관도 0.95~0.998로 같은 크기의 오차. 회귀/분류 순서 뒤바뀜 아님(교차 비교 상관 0.24).
  - 이름 매칭(`classification`/`regression`)은 컴파일된 xmodel에서 올바르다. 입력 스케일 64.0(고정), 출력 스케일 0.0625/0.125는 기존 SSD와 동일 구조.
  - 점수 ≥0.3 검출의 일치율(IoU ≥0.7, 같은 클래스): 보드 기준 0.75~0.80, 호스트 기준 0.67~0.69.
  - 이미지당 검출 수가 NMS 상한(300)에 항상 도달하므로 낮은 점수 꼬리가 서로 크게 다르다(최대 좌표 차이 1,350은 낮은 점수 후보의 좌표 폭주 때문).
- 불일치의 원인을 층 단위로 분리하지는 않았다. 확인된 것은 (a) 보드 출력이 호스트 시뮬레이션과 상관 0.98~0.99로 같은 구조의 값을 내고 회귀/분류가 뒤바뀌지 않았다는 점, (b) 호스트 시뮬레이션과 FP32 사이에도 비슷한 크기의 오차(상관 0.95~0.998)가 있다는 점뿐이다. SSD 헤드는 이미지당 3,234개 후보에서 낮은 점수 꼬리가 NMS 상한 300을 채우므로, 작은 수치 차이가 검출 리스트에는 크게 보인다. 보드의 정수 연산이 호스트 시뮬레이션과 다른 이유(예: 연산 근사 방식)는 추정일 뿐 검증하지 않았다.
- 보드 점수가 호스트 INT8보다 낮은 정도(야간 Lowlight 0.2122 vs 0.2477, 주간 Normal 0.3589 vs 0.5882)는 **YOLO(보드=호스트, 완전 일치)와 크게 다르다**. 호스트 INT8 점수를 보드 점수로 쓸 수 없고, 이 차이는 보드/호스트 연산 불일치로 미해결이다.
- 결과적으로 **SSD 보드 점수의 기준은 보드 DPU 값**이다. 호스트 INT8(야간 Lowlight 0.2477/0.2485/0.2494)과 보드(0.2122/0.2118/0.2076)는 다르다.

### 불일치 위치 분리 (정수 기준값 대조, 2026-10-15)
- 방법: Vitis AI NNDCT `deploy_check`로 양자화기가 만든 **정수 기준값**(xmodel과 같은 고정소수점 값)을 진단 이미지 4장(야간 Lowlight/Normal, 주간 Normal/Lowlight)에 대해 만들고, 보드 DPU의 int8 출력과 직접 비교. 입력·가중치·컴파일 모델은 같다.
- **입력 양자화: 보드와 기준값이 비트 단위로 일치**(307,200바이트 전부 동일, 4장 모두).
- **검출 헤드 레벨별 정확 일치 비율(4장 모두 같은 경향)**:
  - 20×20(앵커 2,400개): 분류·회귀 모두 **100% 일치**(최대 차이 0).
  - 10×10(600): 분류 일치 2%, 평균 차이 10.5~13.6, 최대 53; 회귀 일치 14~16%, 평균 2.2~2.4.
  - 5×5(150), 3×3(54): 일치 0~27%, 평균 차이 분류 9~17, 회귀 1.4~2.7.
  - 2×2(24), 1×1(6): 일치 0~66%.
- 해석(확인된 범위): 어긋남은 **10×10 이하 해상도의 깊은 층에서 시작**하고 20×20 계열에는 없다. 해당 구간의 서브그래프에는 Squeeze-Excitation(전역 평균 풀링 `pool-fix` + `hard-sigmoid-fix`), 10×10 해상도의 hard-sigmoid/hardswish(`hsigmoid_in`·`shift_hsigmoid` 고정소수점 설정), 깊이별 컨볼루션이 있다. 그러나 이 데이터만으로는 어긋남이 어느 연산에서 시작되는지 **분리하지 못했다**: 보드 러너가 최종 출력 2개만 노출하고 중간 텐서는 읽을 수 없어서다. 즉 원인은 아직 "DPU 컴파일/실행과 양자화기 기준값의 불일치(10×10 이하 구간)"까지만 좁혀졌다.
- 결과의 해석: 보드의 SSD 출력은 20×20 레벨에서는 정확하고 낮은 해상도 레벨에서 오차가 크다. 낮은 해상도 레벨은 큰 객체를 담당하므로 객체 크기에 따라 정확도 손실이 다를 수 있다(검증하지 않음). 기존 배포 SSD도 같은 실행 경로를 쓰므로 기존 대비 비교는 같은 조건이다.
- 가능한 후속(미실행): ① 서브그래프를 20×20 이후에서 나눠 중간 텐서를 출력으로 추가하여 첫 어긋남 층 특정(재컴파일 필요), ② SE 블록의 hard-sigmoid 구현을 DPU 지원 버전으로 교체 후 재양자화, ③ 컴파일러 버전·옵션 확인. 모두 모델/컴파일 변경이라 별도 승인 필요.

### 첫 어긋남 층 특정 (이분 탐색, 2026-10-15)
- 방법: 같은 가중치·보정 128장·입력 계약으로 백본을 중간까지만 자른 **진단 전용 xmodel**을 단계별로 양자화·컴파일하고(출력 텐서 1개), 보드 DPU의 int8 출력을 NNDCT `deploy_check` 정수 기준값(진단 이미지 0, 2)과 비교. 배포 모델은 건드리지 않음. FP32에서 진단 모델과 배포 모델의 출력 차이 0.0.
- 비트 단위로 일치(4장 모두 exact=1.0000): 입력, features[0] 끝(20×20), features[1][0] 전체(dw 스트라이드2 → SE → 투영, 10×10), features[1][1]의 확장 1×1 컨볼루션과 깊이별 컨볼루션(+hardswish).
- **처음 어긋나는 곳: features[1][1]의 SqueezeExcitation 내부**(480채널). SE 내부 단계별 비교:
  - 전역 평균 풀링, fc1, ReLU, fc2: 모두 **100% 일치**.
  - **hard-sigmoid(scale_activation): 0% 일치.** 기준값은 전부 64(=0.5, fix_point 7)인데 보드는 0(또는 1)을 낸다. 해석적으로 relu6(x+3)/6을 계산하면 기준값과 오차 0.004 이내, 보드와는 0.50 차이: **보드 출력이 틀리다.**
  - 이 값이 SE의 채널 게이트라 곱셈 뒤 특징맵이 0에 가깝게 된다(b1_se 일치율 9%, 평균 차이 9~10). 이후 b1_proj·b2·c3 및 모든 10×10 이하 헤드 레벨로 오차가 전파된다.
- **상관 관계(인과 미검증)**: 컴파일된 xmodel의 SE hard-sigmoid 8개 중 `hsigmoid_in=11, shift_hsigmoid=18`인 것은 features[1][1]·[1][2]의 480채널 두 개뿐이고, 나머지(`hsigmoid_in` 5/6/8)는 20×20 헤드와 features[1][0]에서 보드가 정확히 재현한다(5와 8 포함). SE의 fc2 가중치가 작은 블록일수록 `hsigmoid_in`이 크다(fc2 가중치 absmax: features[1][1] 0.018, features[1][2] 0.033 → 둘 다 11; features[1][0] 0.074 → 8; features[0][12] 0.73 → 5). 양자화기가 fc2 출력에 높은 소수점 위치(11)를 준 것이 원인 후보이다. 이 SE의 게이트 값은 실제로 ≈0.5±0.01(기준값 63~65/128)로 사실상 상수다. 단, 보드가 `hsigmoid_in=8`은 맞게 계산하므로 한계가 8과 11 사이 어딘가라는 점만 말할 수 있고 정확한 한계는 모른다.
- **기존 배포 SSD도 같은 구조**다: 기존, s1, s2 xmodel 모두 동일한 두 SE 블록이 `hsigmoid_in=11, shift=18`을 가진다. 따라서 과거 SSD 보드 결과 전체(기준선 포함)가 같은 결함의 영향을 받았을 가능성이 있다. 기존 SSD에서 같은 어긋남이 실제로 발생하는지는 이번에 직접 확인하지 않았다(기준값을 만들지 않음).
- 미검증/한계: hsigmoid_in=11이 원인이라는 인과(예: DPU 하드웨어의 입력 소수점 위치 한계)는 확인하지 않았다. 진단 이미지는 4장이고 정수 기준값은 2장에서 단계별로 비교. 아래 수정안은 승인 전이며 아직 실행하지 않았다.
- 수정 후보(미실행, 모델·양자화 변경이라 별도 승인): (a) 해당 두 fc2 출력의 고정소수점 위치를 8 이하로 제한하여 재양자화(게이트 값이 ≈0.5로 거의 상수라 수치 영향은 작을 것으로 예상, 검증 필요), (b) 해당 두 SE의 hard-sigmoid를 CPU로 내리거나 상수 게이트로 대체, (c) 둘 다 시도 후 개발 검증과 보드 정수 대조로 선택. 효과는 보드 정수 대조(일치율)와 개발 검증 mAP로 판단하며 시험 점수로 선택하지 않는다.
- 원자료: `v2_model_pilot/ssd/diag_bisect/` (단계별 보드 출력 npz, 비교 스크립트, 진단 모델 스크립트).

### 수정 후보 1 시험: SE fc2 고정소수점 위치 제한 (2026-10-15)
- 방법: 보정된 시드 0 양자화 설정(`quant_info.json`)을 복사해 두 SE fc2 출력(`nndct_conv2d_117`, `nndct_conv2d_129`, 보정값 11)만 K로 바꾸고 다시 내보내 컴파일. 가중치·보정 데이터는 그대로. K=8과 K=7 두 값을 시험했다.
- 컴파일된 모델에서 해당 두 SE의 `hsigmoid_in`이 11→K(8 또는 7)로 바뀌었고 DPU 서브그래프는 1개 그대로.
- **보드 정수 일치(시드 0, 진단 이미지 0·2, 분류+회귀 전체 3,234×4개씩)**:
  - 원래 모델: 분류 74.7~74.9%, 회귀 78.3~78.4% 일치(10×10 이하 레벨은 거의 0%).
  - **K=8: 분류·회귀 모두 100.000% 일치**(6개 레벨 전부, 최대 차이 0).
  - **K=7: 같은 100.000% 일치.**
  - 즉 SE hard-sigmoid의 `hsigmoid_in`을 8 이하로 제한하면 보드가 양자화기 기준값을 비트 단위로 재현한다. 원인 가설(`hsigmoid_in=11`이 보드 한계 초과)이 맞다는 강한 증거이다(단일 모델·2장, 한계값이 9·10 중 어디인지는 모름).
- **개발 검증 mAP(호스트 시뮬레이션)는 거의 그대로**: 야간 Normal 0.2881→0.2883(K=8)/0.2886(K=7), 야간 Lowlight 0.3035→0.3026/0.3028, 주간 0.7030→0.7027/0.7028. 게이트가 ≈0.5로 거의 상수라 예상대로 수치 손실이 없다.
- 선택: K=8을 기본으로 하되 K=7과 동등하므로 임의로 K=8을 택한다(개발 검증 차이 ≤0.0003). 선택은 정수 일치율과 개발 검증으로만 했고 시험 점수는 보지 않았다.
- 이 수정은 **보드 실행 경로의 결함을 고치는 것**이며, 같은 양자화의 호스트 시뮬레이션 수치를 보드가 재현하게 만든다. 모델 정확도 개선이 아니다.
